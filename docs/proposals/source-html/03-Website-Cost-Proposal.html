Executive summary

Recommendation: build on Umbraco, a free, open-source content management system, self-hosted on a budget ASP.NET Core plan. The CMS itself has no license fee — the money goes entirely to hosting, not software. This keeps the site inexpensive to run indefinitely while meeting the compliance and security bar the business needs.

Advertising as a way to offset costs was evaluated and is deferred to a future phase — not part of this proposal (§08). It doesn't change the recommendation below either way: infrastructure cost is already low enough that self-funding isn't the deciding factor.

01

Framing: this is a cost center, and that's fine

Keep the north star from the main plan in view before looking at any number below.

The site's job is compliance credibility and marketing support for a business whose real revenue comes from ore shipments worth six to seven figures. It is not expected to pay for itself. That reframes every decision in this document: the goal isn't the cheapest possible setup at any cost to security — it's spending as little as responsibly possible while never being the reason a deal falls through or a compliance review goes badly.

Keep this number in your head Every recurring budget figure in this document is under $250/year in its self-hosted form — and the recommended tier is under $80. Compare that to the ~$39.86M single shipment referenced in the main plan's research section — this is not where the business should be cost-sensitive in absolute terms, even though it's still worth doing properly and cheaply.
02

What actually costs money

Five buckets. Only one of them has a hard floor that must be paid in cash.

1 · Infrastructure

Domain, hosting, database, CDN. The only bucket with a hard minimum floor — someone has to run a server somewhere. Covered in §03.

2 · Platform & licensing

The CMS software itself. Covered separately in §04, because it deserves its own answer: is Umbraco really free, and what are the optional paid layers around it?

3 · Security & reliability

Backups, monitoring, patching, SSL. Mostly free or built into the hosting choice — covered in §05, where "secure" and "cheap" turn out not to conflict much.

4 · People time

Whoever applies updates, checks backups, and makes content-model changes. Free if Randolf does it as-is; a real budget line if it's ever outsourced. Covered in §06.

5 · Content upkeep

Fresh photos, updated certificates, a translated page if the bilingual roadmap item happens. Irregular, client-driven, not a recurring bill.

03

Infrastructure — two self-hosted options

The difference between these tiers is operational convenience, not security posture. Neither one is "the insecure option." (A third, fully-managed option is covered in §04 alongside the rest of the Umbraco-specific costs.)

Tier A — Minimum Secure

Budget ASP.NET host + SQLite. Deploy via FTP or a simple CI push. Good default for year one.

Tier B — Managed (Azure)

Azure App Service + Azure SQL. Staging slots, built-in monitoring, easier to scale if traffic or team grows.

04

The Umbraco platform itself

Answering directly: yes, the CMS software has its own cost structure, separate from where it's hosted. Here's every layer of it.

The core is genuinely free

Umbraco CMS is licensed under MIT — free to use, modify, and run commercially, with no user limit, no revenue threshold, and no expiry. This is not a "free trial" or a "community edition" with restrictions; it's the same software Umbraco's largest enterprise customers run. There is no license cost anywhere in Tier A or Tier B above.

Umbraco Cloud is a legitimate product — it removes almost all server-management work by bundling hosting, backups, and a deployment pipeline with a support contract. It's not recommended here because that convenience is priced for teams without an in-house .NET developer, which this project isn't. Worth revisiting only if the site outgrows self-hosting or the maintenance arrangement in §06 changes materially.

Umbraco Forms — why it's being skipped

Umbraco Forms lets a non-technical editor build new forms from the backoffice without a developer. It's a real feature with a real (quote-based, not publicly fixed) price. This proposal skips it because the site only needs one form for the foreseeable future — the contact/inquiry form — and a developer hand-building one form in Razor is a few hours of work, once, for free, versus an ongoing license for a form-builder tool that would mostly sit idle. If the site later needs many different forms edited frequently without developer involvement, this is worth re-pricing.

Umbraco commercial support — why it's being skipped

Umbraco HQ sells direct support contracts for self-hosted installs, priced case-by-case (roughly comparable in scale to the Cloud support tiers — from around $40/month up to four figures for enterprise-grade SLAs). This is a substitute for having a developer on hand, which the site already has. Revisit only under Scenario 3 in §06, if there's ever a period with no developer relationship in place at all.

05

Secure without spending more

The honest answer to "can we save money without cutting security corners": yes — almost everything that actually matters here is free. What costs money is convenience, not safety.

Free and non-negotiable — do these regardless of tier

HTTPS via free host/Let's Encrypt cert Security headers (CSP, HSTS, X-Frame-Options) in ASP.NET Core middleware 2FA on the Umbraco backoffice Cloudflare Free WAF + DDoS protection Scripted offsite backups NuGet dependency updates on a monthly cadence Least-privilege editor role for the owner

Paid — nice to have, skip for v1

Cloudflare Pro ($20/mo) — faster WAF rule tuning, image optimization Managed uptime/status page (Pingdom, Better Uptime paid tiers) Umbraco Cloud (§04) — bundles hosting, deploy pipeline and support Third-party security audit / penetration test

None of the paid items above address a gap the free list leaves open for a site of this size and traffic. Revisit them only if the site starts handling something more sensitive than a contact form — e.g. a buyer login portal down the line.

06

The real variable: people time

Infrastructure and licensing are the easy numbers. This is the one the owner and the developer actually need to agree on — this document intentionally doesn't assume an answer.

Scenario 1 — Developer maintains it, no charge

$0/mo. Fine as long as it's genuinely sustainable long-term. The risk is informal: no SLA, best-effort turnaround, dependent on one person's availability.

Scenario 2 — Light paid retainer

₱2,000–6,000/mo (~$32–97), in line with the Philippine market rate for a "basic" plan (updates, backups, a few support hours). Turns an informal favor into a predictable line item.

Scenario 3 — Outside help takes over

₱6,000–25,000/mo (~$97–404) depending on scope, if the original developer is ever unavailable. Umbraco's talent pool is smaller than WordPress's but real.

Whichever scenario is chosen, put it in writing once — even a one-paragraph email between the owner and the developer — so "who fixes it if it breaks" isn't ambiguous later.

08

Deferred to a future phase Not in this proposal

Advertising was explored as a way to help offset hosting/maintenance cost. It's set aside for now — kept here only as a reference for later, not as something being asked for approval today.

Why it's parked, not pursued Infrastructure cost is already low enough (§03, §07) that offsetting it isn't the deciding factor for this project. Ad income would also be minor at this site's realistic traffic and would arrive slowly (Google withholds AdSense payouts until $100 accumulates). It's better evaluated later, once the site has real traffic data, than built into launch planning now.
